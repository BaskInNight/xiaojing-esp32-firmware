MCP23017 映射与实测状态 6 路霍尔、3 个按钮与手势中断统一聚合；三路水阀、UV、耦合热风继电器与蠕动泵由 MCP 控制。INTB → GPIO13，功放 DIN/AMP_SD 分别为 GPIO14/GPIO47；GPA7/GPB7 按手册仅作输出。MCP 地址 0x20、I²C 通信与上电安全基线已在实机验证。

N16R8 · 自制板规划
电源：现图为 VIN → 开关 → VM → SS24 → RY8411 → 5V → RT9013-33GB → 3V3；VM 同时引到两个 XT30。功率回流不得穿过主控/ADC 地回路。
存储限制：N16R8 使用 Octal PSRAM；GPIO33～37 禁止复用，GPIO26～32 为 Flash/PSRAM 总线，同样禁止占用。
调试策略：USB-C 只连接 CH340C，不占用 ESP32 原生 USB GPIO19/20；CH340C 经 UART0 GPIO43/44 下载和输出日志，并由 DTR/RTS 自动控制 EN/BOOT。
条件复用：GPIO40～41 释放 JTAG 后已由固件用于 IBT-2 PWM；GPIO39 已从搅动电机 PWM 释放并标记 NC，GPIO42 保持受限备用。GPIO19/20 保持备用并标注 USB 复用与上电毛刺。GPIO8 可作为新增风扇电源继电器控制脚，但仍需原理图和固件同步落地。

数据手册审计与硬件约束

依据新板 JLCEDA 原生网表、esp32-s3_datasheet_cn.pdf、MCP23017T-ESS.pdf 与板子零件购买清单
ESP32 分配无禁止脚冲突GPIO5 是 ADC1_CH4；GPIO18 支持 PCNT；GPIO38、47、48 属于普通可分配 GPIO。N16R8 对应 3.3V 的 ESP32-S3R8，不属于 GPIO47/48 为 1.8V 的 R8V/R16V 变型。
复用脚有条件可用GPIO40～41 默认为 JTAG，量产固件必须重新配置为 GPIO；GPIO39 本版标记 NC，GPIO42 仅作受限备用。GPIO19/20 默认 USB_D-/D+ 且有高电平毛刺，不接执行器；GPIO43/44 专用于 UART0。
禁止占用GPIO26～32 连接 Flash/PSRAM；N16R8 的 GPIO33～37 参与 Octal PSRAM；GPIO0、3、45、46 是 Strapping 管脚，只保留启动/下载用途或高阻状态。
ZS-X11B 接口结论主板仅引出 PWM/GND/DIR 三线。GPIO21 通过 2N7002 对 ZS_PWM_IN 做 5V 开漏 PWM，主板 5V 经 4.7k 上拉；GPIO1 通过另一颗 2N7002 下拉方向接口中间脚。GPIO2、GPIO39 均为 NC。
MCP23017 中断规则INTB 改接普通 P2 管脚 GPIO13，并使用 4.7k～10k 上拉至 3V3；MIRROR=1、ODR=1。任务中必须读取 A、B 两组 GPIO/INTCAP 才能清除全部中断，ISR 内只置标志，禁止执行 I²C。
MCP、长线与24V负载A0/A1/A2 接地得到 0x20，RESET 需外部上拉；GPA7/GPB7 仅输出。长线输入外置 10k 上拉。24V 阀门使用至少40V、优选60V的3.3V逻辑 NMOS，Gate 独立10k下拉。
新原理图：5V 电源冲突USB-C VBUS 与 RY8411 的 5V 输出当前直接同网；外部 VIN 与 USB 同时接入会互相反灌。必须增加电源路径隔离（推荐 USB VBUS 经肖特基/理想二极管后再入 5V），或用跳帽实现互斥供电。
CH340C / MCP 链路已实机验证CH340C 已通过 COM8 完成下载与日志通信；MCP23017 地址 0x20、GPIO6/7 I²C、GPIO13 INTB 及上电安全基线均已在 REAL 固件启动日志中验证。原理图仍需保留测试点和故障复核记录。
3.3V 稳压器裕量仍需复核RT9013-33GB 额定 500mA；当前固件能稳定运行不等于峰值电流、压降和热裕量已经满足量产。投板前仍应按 ESP32 Wi-Fi/BLE 峰值、MCP、音频和传感器负载复核，必要时升级到额定≥1A器件。
原理图 DRC 与 5V 供电隔离仍需复核此前发现 USB-C VBUS 与 RY8411 5V 输出存在直并风险；当前实机通信成功只能证明现有样机链路可工作，不能证明电源互灌和 DRC 已修复。最终投板前仍需以最新 JLCEDA 原理图/DRC 结果为准。
GPIO2 / GPIO39 已释放GPIO2 不再承担 BRAKE，GPIO39 不再承担 PWM；两脚在本版原理图中均标记 NC，不引出、不加上下拉。
